# 数据查询探索与自助分析平台

面向数据查询编辑器、可视化探索、自助分析看板、数据导出分发、分析笔记协作与查询历史管理的本地化数据分析应用平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/api/query-opt-service.ts  查询优化 / 结果评估：建议、采纳、改写数据集、评估读数
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-explore-selfservice:entries` 这一项，或调用 `resetModule(模块)`。

## 查询优化与结果评估的数据约定

这两个模块共用一套「建议 → 采纳 → 评估」的链路，读写统一走
`frontend/src/api/query-opt-service.ts`。

- **查询优化**（`queryopt`）保存建议过程：`查询标识 / 建议编号 / 原始查询 / 优化后查询 /
  涉及索引 / 涉及分区 / 建议状态 / 评审人 / 评审时间 / 状态路径 / 待核对 / 来源记录`。
- **查询改写数据集**（`data-explore-selfservice:query-rewrites`）保存执行依据：一条建议最多对应
  一条改写记录，`isCurrent` 标记该查询唯一可供评估的版本。建议表与改写数据集分键持久化，
  刷新或再次生成都不会只剩其中一个字段。
- 一条查询可以并存多条建议。已经是「已采纳」的行不会被新草稿覆盖；再次采纳其他建议只会切换
  「当前执行版本」，原已采纳记录降级为历史版本并保留改写查询与分区。重复采纳同一条建议只更新
  评审时间，不新增第二份执行依据。
- 忽略建议只把该行标为「已忽略」，原查询和查询目录保留，它不会成为执行依据；当前执行版本
  不能直接忽略。涉及索引/分区缺失时登记为「待核对」，绝不从其他建议借字段补全。
- **结果评估**（`resulteval`）只读取查询改写数据集中唯一的 `isCurrent` 版本，并展示原查询与
  改写查询的差异、建议编号和来源记录。没有唯一已采纳版本的评估记录保持「待核对」，不能确认评估。
- 「校验并生成查询改写数据集」会先核对缺口再补写：已采纳建议缺失执行依据时，只用该建议自己的
  字段补一份；重复执行是幂等的。旧版只有单个字段的数据会按行原地迁移，原字段保留。
